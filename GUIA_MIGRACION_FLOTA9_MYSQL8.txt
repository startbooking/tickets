3) PASO 1 - CREAR LA CUENTA Y EL PROYECTO EN GOOGLE
--------------------------------------------------------------------
  1. Crear cuenta de Google (si no la hay).
  2. Entrar a Google Cloud Console:
       https://console.cloud.google.com
  3. Activar la prueba gratis / vincular billing (pide tarjeta,
     pero el free tier y la cuota gratuita NO cobran).
  4. Crear proyecto:  "travelsoft-db"
  5. Confirmar que la facturacion esta vinculada al proyecto.

--------------------------------------------------------------------
4) PASO 2 - CREAR LA BASE DE DATOS MySQL 8
--------------------------------------------------------------------
  OPCION A - CLOUD SQL (recomendada):

    gcloud sql instances create flota9-db \
      --database-version=MYSQL_8_0 \
      --tier=db-g1-small \
      --region=us-central1 \
      --cpu=shared --memory=1.7GB

    gcloud sql databases create flota9 --instance=flota9-db

    # crear usuario
    gcloud sql users create developer \
      --instance=flota9-db --password='123456'

    # autorizar la IP desde donde se migrara (la PC / backend)
    gcloud sql instances patch flota9-db \
      --authorized-networks=<IP_PUBLICA_DEL_PC>

  OPCION B - COMPUTE ENGINE (VM manual):

    gcloud compute instances create flota8-vm \
      --machine-type=e2-small \
      --zone=us-central1-a \
      --image-family=ubuntu-2404-lts-amd64 \
      --image-project=ubuntu-os-cloud \
      --boot-disk-size=20GB

    # luego dentro de la VM:
    sudo apt update && sudo apt install -y mysql-server
    sudo systemctl enable --now mysql
    sudo mysql -e "CREATE DATABASE flota9 CHARACTER SET latin1;"
    sudo mysql -e "CREATE USER 'developer'@'%' IDENTIFIED BY '123456';
                   GRANT ALL PRIVILEGES ON flota9.* TO 'developer'@'%';
                   FLUSH PRIVILEGES;"

5) PASO 3 - HACER EL DUMP EN EL ORIGEN (MySQL 5.0)
--------------------------------------------------------------------
  En la PC actual, ejecutar (horario de baja carga, bloqueara
  escrituras por ser MyISAM):

    mysqldump -h 181.143.144.2 -u developer -p123456 \
      --databases flota9 \
      --lock-tables \
      --routines \
      --triggers \
      --default-character-set=latin1 \
      --result-file=/tmp/flota9_dump.sql

  Verificar que el archivo este completo:
    ls -lh /tmp/flota9_dump.sql        (esperar ~1.5-2 GB)
    grep -c "CREATE TABLE" /tmp/flota9_dump.sql   (esperar 121)

--------------------------------------------------------------------
6) PASO 4 - TRANSFERIR Y IMPORTAR EN EL DESTINO (MySQL 8)
--------------------------------------------------------------------
  A) Transferir el dump al servidor nuevo:

     OPCION A (Cloud SQL): no hay shell; importar con gcloud:
       gcloud sql import sql flota9-db /tmp/flota9_dump.sql \
         --database=flota9

     OPCION B (VM): copiar por scp y luego importar:
       gcloud compute scp /tmp/flota9_dump.sql flota8-vm:/tmp/
       gcloud compute ssh flota8-vm -- \
         'mysql -u developer -p123456 flota9 < /tmp/flota9_dump.sql'

  B) Verificar integridad:
       mysql -h <NUEVO_IP> -u developer -p123456 -e \
         "SELECT COUNT(*) FROM information_schema.TABLES
          WHERE table_schema='flota9';"    (esperar 121+8)

7) PASO 5 - OPTIMIZACION POST-MIGRACION (recomendado)
--------------------------------------------------------------------
  A) Convertir tablas a InnoDB (motor recomendado en MySQL 8):
       SELECT CONCAT('ALTER TABLE flota9.`', TABLE_NAME,
         '` ENGINE=InnoDB;') FROM information_schema.TABLES
         WHERE table_schema='flota9' AND engine='MyISAM';
     (ejecutar el resultado de la consulta)

  B) Convertir a utf8mb4 (acentos/emojis correctos):
       SELECT CONCAT('ALTER TABLE flota9.`', TABLE_NAME,
         '` CONVERT TO CHARACTER SET utf8mb4;') FROM
         information_schema.TABLES WHERE table_schema='flota9';
     (ejecutar el resultado)

  C) Re-verificar counts tabla por tabla vs el origen.

  D) Ajustar parametros del servidor MySQL 8 (en my.cnf):
       innodb_buffer_pool_size = 1G     (segun RAM de la VM)
       max_connections        = 300
       wait_timeout           = 60
       interactive_timeout    = 300
       default-authentication-plugin = mysql_native_password
         (solo si clientes viejos no soportan caching_sha2_password)

--------------------------------------------------------------------
8) PASO 6 - CUTOVER (cambio de servidor)
--------------------------------------------------------------------
  1. Apuntar el backend al nuevo servidor:
       editar /var/www/backend.lan/travelsoft/.env
         DB_HOST=<NUEVO_IP>
         DB_PORT=3306
         DB_USER=developer
         DB_PASSWORD=123456
         DB_DATABASE=flota9
       reiniciar: systemctl restart travelsoft
  2. Probar login + flujos principales (despacho, tiquetes, impresion).
  3. Confirmar que la app web (travelsoft.plus) funciona via tunel.
  4. Mantener el servidor viejo como respaldo/rollback por unos dias.

--- TABLA: resoluciones ---
  Razón: El backend usa esta tabla para:
    - _get_resolucion_activa(id_orides) → SELECT * FROM resoluciones
      WHERE id_orides = ? AND activa = 1
      AND (vigencia_hasta IS NULL OR vigencia_hasta >= CURDATE())

      LAST_INSERT_ID(consecutivo_actual + 1)

  DDL recomendado:
  CREATE TABLE resoluciones (
      id_resolucion INT AUTO_INCREMENT PRIMARY KEY,
      id_orides INT NOT NULL DEFAULT 0,
      numero_resolucion VARCHAR(40) NOT NULL,
      prefijo VARCHAR(10),
      rango_inicial BIGINT,
      rango_final BIGINT,
      consecutivo_actual BIGINT NOT NULL DEFAULT 0,
      fecha_resolucion DATE,
      municipio VARCHAR(120),
      vigencia_desde DATE,
      vigencia_hasta DATE,
      activa TINYINT(1) NOT NULL DEFAULT 1,
      notas VARCHAR(255)
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

  CREATE INDEX idx_resol_activa ON resoluciones (id_orides, activa);

    fecha_llegada     DATE

    estado_sitio      VARCHAR(20)
    numero_orden      VARCHAR(6)   (después de placa_vehi_original)
  Razón: Estas columnas son usadas por:
    - reportar_llegada(): UPDATE rutas SET llegada_ruta='1',
      hora_llegada=..., fecha_llegada=..., estado_sitio=...
    - getDashboardCajero(): SELECT ... WHERE llegada_ruta = '1'
    - getLlegadas(): SELECT ... llegada_ruta, estado_sitio FROM rutas
    - getResumenEnTransito(): WHERE llegada_ruta = '1' AND despachada_ruta = '0'
    - NuevaRutaDialog: numero_orden para la ventanilla de Secretaría

--- TABLA: planillas ---
  Agregar:
    forma_pago        CHAR(20) DEFAULT 'EFECTIVO'
  Razón: INSERT en planillas durante vender_tiquete incluye forma_pago
    (EFECTIVO|TARJETA|QR). Usado en reportes de cierre y liquidación.

--- TABLA: usuario ---
  Agregar:
    rol              ENUM('SUPERADMIN','ADMIN','AGENCIA','CAJERO','DESPACHADOR')
                    DEFAULT 'CAJERO'
    password_hash     VARCHAR(255)
    token_version     INT DEFAULT 0
    created_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    updated_at        TIMESTAMP DEFAULT CURRENT_TIMESTAMP
                    ON UPDATE CURRENT_TIMESTAMP
  Razón: El backend SACTel.Cloud usa password_hash + bcrypt para login,
    rol para autorización y JWT. La columna clave_usuario existe pero
    el código usa password_hash. Si se usa clave_usuario, adaptar el login.
